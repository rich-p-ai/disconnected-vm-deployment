HOW TO COPY A VM (POD WAY)
Read this. Do the steps in order. Stop if a step fails.

You need the vm-tools folder on the bastion.
You need to be logged in with oc.
Do not use sudo.

The disk class name is:  lvm
(Ask if oc get storageclass lvm fails.)

--------------------------------
WHAT YOU ARE DOING
--------------------------------
1. On the FIRST cluster, you pack the VM into small files.
2. You copy those files on a USB stick.
3. On the NEXT cluster, you make a new VM from those files.

The computer in the cluster does the heavy work.
The bastion only starts the job and holds the small files.

Do not copy any file that ends with .raw
Only copy files that end with .raw.gz and the paper files with them.

--------------------------------
BEFORE YOU START
--------------------------------
1. Open a terminal.
2. Go to the vm-tools folder.
      cd vm-tools
3. Make the buttons work.
      chmod 0750 build dest cleanup
4. Log in.
      oc login
5. Check who you are.
      oc whoami
   You should be a cluster admin.
6. Check the disk class.
      oc get storageclass lvm
7. Clean old jobs first.
      ./cleanup

--------------------------------
CLEAN OLD JOBS
--------------------------------
If a build failed, or you are not sure, run this first.

  ./cleanup

That looks in the whole cluster for old abc-build and abc-dest jobs.
It deletes those jobs and their work disks.
It does NOT delete your VMs.
It does NOT delete vm-catalog.

One project only:

  ./cleanup --namespace vms

One job only:

  ./cleanup --namespace vms --job abc-build-windows-0-1-0-test

--------------------------------
PART A  PACK THE VM (SOURCE)
--------------------------------
Log in to the FIRST cluster.

The VM must be off. If it is on, turn it off first.

  virtctl stop <vm-name> -n <project>

Type this. Put in your names.

  ./build \
    --namespace <project> \
    --vm <vm-name> \
    --version 0.1.0 \
    --storage-class lvm \
    --transfer-dir /tmp/vm-transfer \
    --clean

Wait. This can take a long time.

GOOD:
  A folder shows up under /tmp/vm-transfer/
  It has files that end with .raw.gz
  It has a file named checksums.sha256
  It does NOT have files that end with .raw

Check the files:

  cd /tmp/vm-transfer/<vm-name>-0.1.0
  sha256sum -c checksums.sha256

If that says OK, you are done with Part A.

BAD:
  Copy the last lines on the screen.
  Run ./cleanup
  Do not run ./build again until cleanup is done.

--------------------------------
PART B  CARRY THE FILES
--------------------------------
Copy the whole folder from Part A onto the USB stick.

Only copy the folder that has .raw.gz files.
Do not copy .raw files.

Take the USB to the next site.

--------------------------------
PART C  MAKE THE VM (DEST)
--------------------------------
Log in to the NEXT cluster.

  chmod 0750 build dest cleanup
  oc login
  oc whoami
  oc get storageclass lvm
  ./cleanup

Put the USB folder on the bastion. Then:

  ./dest \
    --bundle-path /path/to/<vm-name>-0.1.0 \
    --storage-class lvm \
    --catalog-namespace vm-catalog \
    --namespace <user-project> \
    --vm-name <new-vm-name> \
    --clean

Wait. This can take a long time.

GOOD:
  oc get vm <new-vm-name> -n <user-project>
  The VM is there and stopped.

Start it only after you look at it:

  virtctl start <new-vm-name> -n <user-project>
  oc get vmi <new-vm-name> -n <user-project>

BAD:
  Copy the last lines on the screen.
  Run ./cleanup
  Do not run ./dest again until cleanup is done.
